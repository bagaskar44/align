## Hasil implementasi

- `packages/domain/src/align_domain/executor.py` menyediakan evaluator applicability tertutup, stable DAG, chunking/tokenizer manifest, BM25, cosine 1536, RRF, validators typed untuk observation/quote/role/batch, category gates, fingerprint dan dedup key.
- `services/api/src/align_api/analyses.py` membatasi run ke submission final, spec schema-2 approved dan release immutable. Run dan response mengikat fingerprint, coverage, grounding, candidates, limitations dan routing outcomes.
- `services/worker/src/align_worker/executor.py` menyimpan check semua elemen, memproses DAG secara topological, mempertahankan failed/unreadable units dalam inventory/denominator, memperluas top-k kosong ke semua unit kompatibel, dan memakai BM25 + exact pgvector cosine dengan filter submission/version/owner/course/assignment sebelum ranking. Executor kini memanggil adapter embedding untuk indexing chunk dan query vector, memvalidasi dimensi 1536, scope, manifest, usage, token cap dan hasil batch; `PaidCallBlocked` dicatat sebelum jaringan. Tidak ada ANN index.
- Jalur mock memakai vector lexical-hash sintetis berlabel, tidak terlatih dan bukan bukti kualitas retrieval. Unit test memakai fake `ProviderResult` non-network untuk membuktikan plumbing embedding executor; itu bukan panggilan OpenAI/provider nyata.
- Pemeriksaan semantik terhubung sebagai tahap terpisah dari validasi kutipan/anchor/role. Kandidat positive hanya dapat lolos typed semantic verdict dengan claim dan evidence dalam scope. Absence memerlukan pemindaian semua compatible source units dalam batch, dan setiap segmen harus dijawab verifier sebagai `unsupported`; empty top-k, unit yang unreadable/partial, insufficient result, kegagalan provider, atau batas token/call mempertahankan gate tertutup. Uji unit memakai verifier synthetic test-only untuk membuktikan kontrol alur lengkap dan jalur insufficient; ini tidak membuktikan kebenaran semantik suatu karya.
- `packages/domain/src/align_domain/providers.py` memiliki adapter OpenAI Responses dan embedding dengan konfigurasi model, schema/usage typed, serta mock fixture berlabel. `PaidCallBlocked` berhenti sebelum `urlopen`; tidak ada live call. Reservation, tariff, settlement dan reconciliation tetap prasyarat B6.
- Migration `0011_b5_executor.py` menambah run/stage, retrieval/vector, coverage, grounding, routing, batch-member dan candidate link tables. `0012` menambah feedback provenance; `0013` mengantrekan model feedback; `0014–0015` memberi worker read access yang diperlukan serta update terbatas pada kolom draft/timestamp. Worker tetap tidak dapat menulis keputusan, approval atau publication.
- B4 feedback kini memakai `job.execute` outbox + fenced worker. API mengembalikan draft berstatus queued; worker memakai hanya selected confirmed findings dan bukti aktif, memvalidasi ulang ID/criterion/evidence dan menghasilkan fallback template pada failure. Routing memakai role efficient untuk `draft_feedback` sesuai baseline, sedangkan task semantik interpret/verify tetap complex, batch size 1. Review lama tidak ditulis ulang. UI menunggu worker dan tidak mengizinkan approval sebelum generation selesai.
- Drafting B1/B2 memakai adapter provider yang sama melalui `context_provider.py` dan `drafting.py`, dengan validasi referensi sumber dan persetujuan dosen tetap wajib. Mock B1/B2 secara eksplisit abstain tanpa usulan semantik; UI/E2E memeriksa label simulasi dan abstention itu, bukan memaksa temuan agar tes lulus. Jalur configured/live berhenti di guard pembayaran.
- Keputusan engineering lokal: B5 memakai tabel domain ternormalisasi dan job/outbox umum B0. Profil Compose test memakai Redis queue prefix `align-test`, dispatcher dan parser worker khusus agar job test tidak dikonsumsi worker development pada prefix `align-dev`; ini diperlukan untuk reproduksi recovery test yang deterministik dan tidak mengubah antrean development. Mode executable `docker/postgres/init/001-roles.sh` diperbaiki supaya role initializer berjalan pada checkout/database baru. Tidak ada dependency/lockfile baru atau perubahan batas resource. `tests/integration/conftest.py` memakai fixture B4 bersama agar regresi B4 dan B5 berjalan pada scenario terisolasi yang sama.

## Fixture dan bukti runtime

Semua integrasi B5 dijalankan pada project Compose terisolasi `align-b5-gate` dan role DB `align_worker`; tidak menggunakan database development. Fixture `tests/fixtures/b1/native-two-pages.pdf` dibaca dengan pypdf oleh integration setup: teks dua halaman diperiksa, lalu evidence dan satu unit halaman `unreadable` dipasang pada fixture DB. Ini menguji executor dari source-derived evidence, tetapi **bukan** end-to-end rerun parser B3.

Analysis run mock/synthetic mempertahankan unit unreadable sebagai `unresolved`, `exhaustive_for_negative=false`, dan tidak menghasilkan absence candidate. Tes unit terpisah memasukkan seluruh segmen source ke verifier test-only non-network: hanya rangkaian lengkap yang seluruhnya dinilai unsupported menjadi exhaustive; satu segmen insufficient menutup gate. Ini membuktikan mekanisme pembukuan/batas, bukan klaim semantik terhadap source nyata. Pengujian menyisipkan chunk dan embedding synthetic untuk owner asing ke pgvector; `_vector_rank` tidak mengembalikannya untuk submission target. Ini bukti isolasi owner pada PostgreSQL/pgvector nyata untuk kasus tersebut, bukan seluruh kombinasi role/render atau seluruh kemungkinan tenant.

Review lama dengan catatan manusia dibuat sebelum analysis baru. Setelah run, accepted finding baru menghasilkan feedback POST `202`, job queued dan outbox `job.execute`; replay dengan key sama mempertahankan `202` serta ID draft yang sama. Edit/approval saat queued ditolak `409`; task `execute_job` memprosesnya menjadi `ready_for_review`, kemudian GET draft memberi `generation_status=completed`. Provider call ledger berlabel mock mencatat fixture `mock:draft_feedback:v1`, usage dalam batas, dan budget draft maksimal USD 0.03. Integration membandingkan lagi catatan, revision dan analysis binding review lama; nilainya tidak berubah. Worker diberi update hanya pada kolom generation/body/hash/timestamp yang dibutuhkan, bukan state approval. Worker juga menolak memanggil provider jika review source sudah stale saat job mulai.
