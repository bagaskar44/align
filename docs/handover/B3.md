# Handover B3 — Submission dan Viewer

Tanggal pembaruan: 21 Oktober 2026 (Asia/Jakarta). B3 selesai pada fixture dan akun sintetis di project Compose terisolasi `align-b3-verify`. B4 belum dimulai. Handover ini melanjutkan [B2](B2.md), [B1](B1.md), [keputusan teknis](../technical-decisions.md), [dokumen implementasi B3](../implementation/B3-submission-dan-viewer.md), [traceability](../../requirements_traceability.md), dan [master](../../ALIGN_IMPLEMENTATION_SPEC.md).

**Status: gate implementasi B3 lulus dalam batas yang dinyatakan di bawah.** AC-MVP-13 baru dibuktikan untuk komponen B3: outbox/job pulih dan parser aktual selesai setelah broker pulih. Acceptance penuhnya tetap pada gate B5. Pengujian memakai data sintetis; tidak membuktikan inference, OCR tulisan tangan, semua file produksi, atau throughput maksimum bundle.

## Perubahan B3

- Migration `0008_b3_submissions` menambah submission/thread, immutable submission version dan roster member snapshot, namespace source/evidence/parser artifacts/checkpoints/time reservations, late/reopen binding dan guards. `0009_b3_upload_retention` menambah retention untuk draft upload/quarantine yang kedaluwarsa.
- `services/api/src/align_api/submissions.py` menambah alur individual/kelompok, upload streaming, finalisasi idempotent dan transactional outbox, status aman, late policy, reopen, source inventory/evidence, unduhan original terotorisasi/range, spreadsheet cells, serta retry/status job yang role-filtered.
- `services/worker/src/align_worker/context_parser.py` memakai parser sumber yang sama dengan konteks/rubrik. Native DOCX/XLSX terikat ke `native_ooxml_v1` 2 GiB; PDF/image memakai Docling `docling_native_v1` 8 GiB. Resource/profile/manifest mismatch berhenti fail-closed; tidak ada fallback ke `docling_light_v1` dan hasil mock tidak disebut hasil parser aktual.
- Inventory mencakup file/container/page/part/sheet sebelum extraction. Anchor dan evidence dikaitkan ke owner, submission version, asset, hash dan manifest. Unit gagal/unsupported tetap ada sebagai limitation.
- `SubmissionWorkspace`, `SubmissionQueue`, `SubmissionViewer`, dan `PdfSourceViewer` menyediakan upload/receipt, queue dosen, PDF canvas + overlay, DOCX structural view, XLSX grid termasuk hidden sheet, dan image original + overlay. Feedback akademik/publikasi dan review tidak ditambahkan.
- `pdfjs-dist` versi terkunci `6.4.299` ditambahkan untuk viewer PDF. `pnpm-lock.yaml` diperbarui sesuai versi tersebut. B3 tidak menambah dependency Python. Perubahan Docling `rtree` di `uv.lock` adalah keputusan B1 yang telah disetujui sebelumnya, bukan dependency B3. Arsitektur layanan tetap API/worker/PostgreSQL/Redis/object storage dan kontrak data hanya diperluas untuk scope B3.
- Fixture sintetis B3 ada di `fixtures/b3/`; `scripts/generate-b3-fixtures.py` mereproduksinya. Perubahan `.vscode/` tidak terkait B3 dan tetap di luar handover.

## Parser benchmark dan batas sumber

Environment benchmark adalah Linux ARM64 dalam VM Docker, 8 CPU, RAM VM `12,526,637,056` byte, container limit `9,663,676,416` byte. Profile hash native `8bbb8e3601515fe7d370acedc3908887e58b6be7065f81b468154440448c3978` dan Docling `aa0f7c31205073a08836f42b7d0b1cb3af373fd6608b1aa53219db1e4bcbc218`. Semua fixture sintetis; tidak ada provider call. Versi dan model/OCR checksum lengkap ada di JSON report.

- Native DOCX: cold/warm 257/255 ms, peak child RSS 38.6 MB, 33/33 anchor terverifikasi dan 10/10 table evidence.
- Native XLSX: 366/316 ms, peak child RSS 47.8/46.8 MB, 22/22 anchor terverifikasi. Hidden sheet dibaca; cache formula belum diverifikasi dan chart/drawing/media hanya diinventarisasi.
- Docling PDF digital dua halaman: 31,936/26,654 ms; PDF scan: 12,353/12,310 ms; PNG: 12,113/13,668 ms; JPEG terputar: 14,304/13,091 ms. Peak child RSS sekitar 1.16–1.19 GB. Seluruh 4/4, 5/5, 4/4, dan 6/6 anchor sample masing-masing valid; nol invalid/unanchored dalam fixture.
- `memory.current` disampling setiap 50 ms untuk seluruh container benchmark, bukan per child; `VmHWM` adalah high-water RSS child. Ini dua pengukuran berbeda dan report tidak menyamakan keduanya. Cold/warm adalah child pertama/kedua pada invocation benchmark; model dimuat ulang tiap child.
- Docling 2.140.0 tidak mengekspos render/layout/OCR/table sebagai timer terpisah pada API conversion yang dipakai. Report mencatat `docling_pipeline_conversion` gabungan dan memisahkan resource/runtime setup, inventory, assembly, preflight dan child wall. Tidak mengarang substage timing.

Limitation: OCR artifact bukan bukti ketepatan tulisan tangan. Rumus XLSX tidak dieksekusi dan cached value tetap unverified. Chart, drawing dan embedded media tetap unsupported kecuali parser memiliki evidence terverifikasi. Hubungan tabel lintas halaman yang meragukan tetap partial. Stress file/bundle maksimum 20 MiB, 100 halaman, 600 detik tidak dijalankan; hasil benchmark sampel tidak membuktikan bundle tersebut selesai di bawah cap.
