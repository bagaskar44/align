- API `services/api/src/align_api/assignments.py` menyediakan assignment/version, criteria/requirements, package/spec/policy approval, lint/resolution, publish, student serialization dan group API. File rubrik tetap privat; `criteria-drafts` meluncurkan `job.parse_rubric` pada parser B1 dengan manifest/admission/checkpoint/lease/fencing/resource guard yang sama. Evidence dan ParseArtifact dibatasi ke AssignmentVersion, file, SHA-256 dan anchor; GET rubrik hanya memberi ringkasan aman. Dosen dapat mengikat evidence rubrik sebagai normative source ref, lalu server memeriksa ulang hash file dan kutipan saat approval paket. Tidak ada bobot/level rubrik yang diubah menjadi skor.
- Mock proposal yang tersedia hanya mengambil excerpt persis dari instruksi asli dan menautkan hash serta offset code point. `mandatory` tetap null; hasil tidak disalin otomatis menjadi kriteria resmi dan tidak ada provider call/biaya.
- `apps/web/src/components/AssignmentWorkspace.tsx` menambahkan alur dosen dan tampilan tugas mahasiswa pada halaman course; `AssignmentStructuredEditors.tsx` menyediakan editor criteria/requirements, source citation code-point, CheckSpecification (derivasi, applicability/fact registry, grounding/roles, evidence, relationship, DAG, abstention dan batas), serta NumericPolicy/conversion. Coverage guardrails tetap terkunci server/client. Respons create-spec membawa state/hash agar editor tampil setelah pembuatan. GET publish-preview memakai serializer publik yang sama dengan mahasiswa dan tidak mengirim DSL internal.
- `fixtures/synthetic/b2-schema1-history.json` adalah payload kompatibilitas sintetis. GET schema 1 dipertahankan; mutasi/lint/approval v2 terhadapnya ditolak. Ini bukan rekaman deployment lama.
- `fixtures/synthetic/b2-semantic-negative.json` memuat conditional obligation dan kutipan persis yang tidak mendukung makna. Lint menerbitkan `condition_fidelity_review`; approval tanpa tinjauan ditolak.
- Test concurrency memakai dua identitas dosen ber-enrollment aktif untuk merace approval paket, approval spec serta publish; setiap operasi menghasilkan satu 200 dan satu 409.

Tidak ada dependency atau lockfile baru untuk B2. `.vscode/` yang tampak untracked pada workspace berasal dari perubahan lokal lain dan bukan bagian handover B2; pertahankan.

## Batas klaim tahap ini

- Parser rubrik menghasilkan evidence yang ditinjau dosen, bukan interpretasi semantik atau pengesahan criteria otomatis. Mock proposal instruksi hanya excerpt literal; tidak ada inference live yang diklaim.
- Belum ada configured provider/schema-repair path khusus criteria generation pada B2. Jalur yang dibuktikan ialah manual draft dan extractive mock tanpa provider call; kegagalan provider criteria-generation live tidak diklaim telah diuji. Editor manual tetap tersedia.
- AC-MVP-50/53 membuktikan bahwa citation mekanis tidak otomatis menjadi dukungan semantik dan menahan approval untuk review. Semantic verification terhadap submission tetap milik B5.
- Acceptance yang dimulai/dituntaskan B3–B8—late submission, retrieval/executor, review evidence dan semantic decision atas submission, numeric execution, robustness/equivalence serta evaluasi empiris—tetap pending pada tahap pemiliknya. Schema B2 tidak dihitung sebagai implementasi tahap-tahap tersebut.

Status rinci per requirement ada pada [overlay traceability B2](../../requirements_traceability.md#overlay-implementasi-b2). Requirement dan acceptance normatif tidak dikurangi; hanya status bukti aktual yang diperbarui. Berhenti pada B2; jangan mulai submission/viewer B3 sampai instruksi tahap berikutnya.
